## 3. 总体复杂度评级

**实习项目基准（0-10）：约 7 / 10（中上）**

- 广度足够：覆盖全栈、AI、算法、部署、安全、版本管理多个面
- 深度足够：LLM 工程化和 diff/量化算法是真正的加分点，不是教程级 CRUD
- 单点不极端：没有分布式、高并发、实时协同这类"超纲"复杂度，符合"不要太难"的目标

## 4. 亮点（面试可讲）

1. **混合评分引擎**：量化层可解释 + LLM 质评层深度，分数可拆解（Quant × 0.4 + Qual × 0.6）
2. **Human-in-the-loop AI 修改**：LLM 只出完整文本，服务端 LCS 计算 diff，用户逐条确认后回放，避免 AI 越权乱改
3. **版本链设计**：parentId 自关联 + 行锁防并发版本号重复 + 共享文件引用计数
4. **Prompt 工程**：6 类任务模板、结构化 JSON 输出、zod 校验兜底、Prompt Injection 防护
5. **工程流程**：每 Phase 文档先行、独立提交、code review 子代理、探针回归清理

## 5. 短板（面试可能会被追问）

| 短板 | 现状 | 建议 |
|------|------|------|
| 自动化测试 | 无单元/集成/E2E 测试，只有手工探针脚本 | 补 matching/diff 单元测试 + 1-2 条核心链路集成测试 |
| 实时性 | AI 分析为同步等待 + loading | 可升级为任务队列 + WebSocket/SSE 进度推送 |
| 鉴权生态 | 仅邮箱密码 JWT | 补 GitHub OAuth（也顺带接入 GitHub 项目数据） |
| 工程化 | 无限流、无迁移文件（仅 db push）、无可观测性 | 加 rate limit、prisma migrate、日志/错误上报 |
| 多租户 | 单用户模型，无团队/权限 | 若做 B 端叙事需 RBAC |
| 生产上线 | 未实际部署 | 用 Vercel + Supabase 真实部署一次，接域名 |

## 6. 与大厂实习项目基准对比

- **达标项**：全栈闭环、AI 应用落地、算法实现、工程规范、部署方案 —— 已达到多数大厂实习项目的"够用"水平
- **拉开差距项**：自动化测试与真实生产部署（这两项补上后，叙事完整度会明显提升）
- **不建议加**：微服务、K8s、高并发中间件 —— 对实习项目是负资产，面试官更愿意看到"把单应用做扎实"

## 7. 结论

OfferPilot 是一个**广度 7 分、AI 深度 8 分、工程规范 7 分**的中上复杂度实习项目。它最独特的资产不是看板/CRUD，而是**"AI 改写 + 用户确认"的协作范式**与**混合评分可解释性**。若要冲更高级别的评价，优先补自动化测试与一次真实部署，而不是继续堆功能。
