# OfferPilot 演示路径

> 用于面试/作品集演示的完整用户旅程。建议提前准备一份真实简历 PDF 和 1-2 个真实 JD。

## 准备

1. 本地启动：`pnpm dev`，打开 http://localhost:3000
2. 注册账号（邮箱 + 密码）
3. 准备文件：`demo-resume.pdf`（可先用你自己的简历）
4. 准备 JD：复制一段真实招聘 JD（Boss直聘 / 拉勾 / 公司官网）

## 演示脚本（约 5 分钟）

### 1. 上传简历并建立分析（60s）

- 进入 `/resumes`，拖拽上传 PDF
- 进入 `/applications/new`
- 选择 2 个目标岗位（如"前端开发工程师" + "全栈开发工程师"）
- 粘贴 JD（或粘贴链接自动抓取，失败时手动降级）
- 点击分析，等待匹配报告生成

**讲解点**：混合评分 = 关键词量化分 × 0.4 + LLM 质性分 × 0.6；
异岗对比展示同一份简历对不同岗位的匹配度差异。

### 2. 查看匹配报告（60s）

- 雷达图展示四个维度评分
- 待补强项（gaps）与优化建议（suggestions）
- 标记投递状态（面试中 / 已拿到 Offer）

**讲解点**：报告包含量化层与质性层分离的分数，方便解释"匹配度怎么算"。

### 3. 简历编辑器 + AI 修改（90s）

- 进入 `/resumes/[id]/edit`
- 点击"AI 智能修改"，选择目标岗位（+ 可选 JD）
- AI 返回行级 Diff：绿色新增 / 红色删除 / 黄色修改
- 逐条接受/驳回，或"全部接受"，应用后保存

**讲解点**：Human-in-the-loop 设计；LLM 只给完整文本，
diff 由服务端 LCS 计算，保证位置可靠、可逐条回放。

### 4. 格式校对（30s）

- 点击"格式校对"，规则引擎秒级返回问题列表
- AI 质评补充表达质量/结构/亮点建议
- "一键修复"自动处理日期格式、标点、拼写、空行

**讲解点**：规则引擎与 LLM 的分工：可解释、快、可自动修复 vs 需要判断。

### 5. 版本控制（30s）

- 编辑器点"另存为新版本"，生成 v2
- 进入版本历史，选择 v1 → v2 对比
- 演示"从该版本继续"（回退派生新版本）

**讲解点**：版本链 = parentId 自关联；列表只显示链头，
对比复用与 AI 修改相同的 diff 工具。

### 6. 模拟面试题（60s）

- 从投递详情进入"模拟面试题"
- 生成 6 题（技术面 3 + 项目面 2 + 行为面 1）
- 记录回答并导出 Markdown

**讲解点**：题目生成基于 JD + 简历 + 岗位画像三重上下文；
重新生成会替换旧题，保持与当前报告一致。

## 常见问题应对

| 问题 | 回答 |
|------|------|
| 匹配度怎么算的？ | 关键词加权 Jaccard 量化 + LLM 多维质评，40/60 加权 |
| AI 会不会乱改？ | 修改必须逐条确认；Prompt 硬性约束不改事实信息 |
| 为什么用 JSON 列？ | 简历/报告结构频繁变化，避免频繁迁移 |
| 部署在哪？ | Vercel + Supabase（或 Docker 自托管，见 README） |
